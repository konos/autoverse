  <action>

다시 읽어 `freshToken` 지역 변수에 담는다. `null` 이면 실행 시작부의 UNAUTHORIZED 블록과 동일한
3단(`_emitError("execute", "UNAUTHORIZED", ...)` + `_setPhase("error")` +
`throw new WeverseApiError("UNAUTHORIZED", ...)`) 처리를 그대로 수행한다 — 새 에러 코드나 새 문구를
만들지 않는다.

대기 이후에 토큰을 소비하는 지점 전부를 `freshToken` 으로 바꾼다: `submitApplication(...)` 의 토큰
인자, `post-submitted` 이벤트의 `tokenPreview`(계속 `maskToken()` 을 통과시킨다), 그리고
`_pollStatus(schema, ...)` 의 토큰 인자. 실행 시작부의 `const token` 은 그대로 남겨
`syncTime(token)` 에만 쓴다 — 시간 오프셋은 토큰 신원에 의존하지 않으므로 옮길 이유가 없고,
옮기면 동기화가 대기 이후로 밀려 타이밍 설계가 바뀐다(D-13 이 명시적으로 그대로 두라고 한
부분이다).

왜 이 재조회가 필요한지를 코드 주석으로 남긴다: 대기 이전에 캡처한 토큰을 그대로 쓰면 사용자가
