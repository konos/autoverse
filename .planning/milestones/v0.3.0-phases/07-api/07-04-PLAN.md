`LoginPanel.tsx` 에 저장 자격증명 스냅샷 상태를 추가한다: `const [storedSnapshot,
setStoredSnapshot] = useState<StoredCredentialsSnapshot>({ state: "none" })`. 마운트 시
`useEffect` 로 `window.api.auth.getStoredCredentials()` 를 호출해 스냅샷을 채우고, 결과가
`available` 이면 이메일 state 를 저장된 이메일로 초기화한다(프리필, D-02). **비밀번호 state 는
절대 건드리지 않는다** — 저장된 비밀번호는 이 컴포넌트에 도달하지 않는다(D-01). 프리필은 사용자가
이미 무언가 입력한 뒤 덮어쓰지 않도록 이메일 state 가 빈 문자열일 때만 적용한다.

파생값 `const storedView = resolveStoredLoginState(storedSnapshot, email)` 를 계산한다.

**저장 상태 블록(D-06/D-07)** 을 새로 렌더링한다. 위치는 API 모드 인라인 안내 문단 아래,
`{status.isLoggedIn && ...}` 버튼 행 위 — 즉 **로그인 여부 조건 밖**이라 미로그인 상태에서도
보인다. 노출 조건은 `loginMode === "api"` 이며(D-07 이 API 탭을 지정했다), 블록 안에는
`storedView.statusLine` 문단, `storedView.notice` 문단(`role="alert"`), 그리고
`storedView.showClearButton` 일 때의 "저장된 로그인 정보 삭제" 버튼이 들어간다. 새 카드/모달을
만들지 않고 기존 `.login-mode-notice` / `.error-message` 문단 스타일과 `.button-row` 관례를
재사용한다(D-15/06).

삭제 버튼 핸들러는 `window.api.auth.clearStoredCredentials()` 를 호출한 뒤 스냅샷을 다시 조회해
상태를 갱신하고 이메일 state 를 빈 문자열로 되돌린다(프리필이 사라지는 것이 삭제의 눈에 보이는
결과다). **로그아웃은 하지 않는다** — 이 버튼은 저장 정보만 지운다.

기존 `{status.isLoggedIn && ...}` 버튼 행에서 "로그아웃 + 자격 증명 삭제" 버튼을 제거한다.
삭제 통제권이 D-07 상태문과 같은 자리로 모이므로 두 버튼이 겹치는 상태를 남기지 않는다.
`onLogout(clearCredentials: boolean)` prop 시그니처와 `auth:logout` 채널의 `clearCredentials`
인자는 그대로 둔다 — 계약은 유지하고 이 화면의 호출만 정리한다. "토큰 검증" 과 "로그아웃"
