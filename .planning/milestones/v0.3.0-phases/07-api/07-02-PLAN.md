    `maskEmail(email: string): string`
    - `"kim@weverse.io"` → `"k**@weverse.io"` (로컬파트 첫 글자 + 나머지 길이만큼 `*`, 도메인 그대로)
    - `"a@b.com"` → `"a*@b.com"` (로컬파트 1글자 → 첫 글자 + `*` 한 개, `maskName()` 의 단일 글자 관례와 동일)

    - `"@"` 가 여러 개면 마지막 `"@"` 를 도메인 경계로 본다
    - 도메인은 절대 마스킹하지 않는다 — 사용자가 어느 계정인지 알아볼 수 있어야 D-07 의 상태문이 쓸모 있다

    - `"emailLen=12"` 같은 진단 로그는 훼손되지 않는다 (키 뒤에 곧바로 `:`/`=` 가 오는 경우만 매칭)

  <action>
`src/shared/mask.ts` 에 `maskEmail(email: string): string` 를 추가한다. 위치는 `maskName()`
바로 아래, `SENSITIVE_PATTERNS` 배열 위. 구현은 마지막 `"@"` 위치로 로컬파트/도메인을 나누고
로컬파트에 `maskName()` 과 동일한 "첫 글자 + `*` 반복" 규칙을 적용하는 형태로, 기존 마스킹
함수들의 짧은 방어적 스타일(빈 값 → 고정 문자열)을 따른다.

`SENSITIVE_PATTERNS` 배열에 email 키 규칙을 추가한다. 정규식은 기존 키-값 관용구
`(email["']?\s*[:=]\s*["']?)([^"',}\s]+)` 를 쓰고 replacer 는 `maskEmail(v)` 를 호출한다. 위치는
**`firstName`/`lastName` 규칙 다음, 배열 맨 끝의 JWT 구조 규칙 앞**이다 — JWT 구조 규칙은 주석이
명시한 대로 반드시 마지막에 남아야 한다. 새 규칙 위에 주석으로 근거를 남긴다: IN-02(06-REVIEW)가
지적한 공백을 닫는 규칙이며, D-07 의 저장 상태문이 이메일을 화면에 노출하므로 로그 경로도 같은
관문을 지나야 한다는 점.

`auth-service.ts` 에서 이메일이 로그로 나가는 두 지점을 이 관문으로 옮긴다. (1) `saveCredentials()`
의 저장 성공 로그는 이메일 앞 3글자를 직접 잘라 쓰는 임시 마스킹이므로 `maskEmail(email)` 호출로
교체하고 `mask.ts` 에서 import 한다(파일 상단에 이미 `maskToken`/`maskSensitive` import 가 있으니
같은 구문에 추가). (2) `credentialLogin()` 안의 헤드리스 입력 상태 진단 로그는 값이 아니라
**길이**를 찍는 라인인데 키 이름이 `email` 이라 새 규칙에 걸려 길이 숫자가 마스킹돼 진단 가치를
잃는다 — 키 이름을 `emailLen=`/`pwLen=` 형태로 바꿔 같은 파일 아래쪽 디버그 덤프가 이미 쓰는
`emailLen` 관용구와 통일한다(값과 의미는 그대로, 이름만 정정).

value in a serialized object string (email preserved)" 을 갱신한다** — 제목의 괄호 부분과
`toContain` 단언을 이메일이 마스킹된 형태를 기대하도록 바꾸고, 비밀번호가 여전히 마스킹된다는
