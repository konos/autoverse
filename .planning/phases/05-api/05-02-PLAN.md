**2) `src/main/services/api-auth-client.ts`**

`async resendOtp(otpSessionId: string): Promise<{ expiresIn?: number }>` 를 추가한다. `POST ${ACCOUNT_API_BASE}/v2/auth/otp`, 바디 `{ otpSessionId }`, 기존 `postAccount` 헬퍼를 그대로 사용해 헤더 6종과 에러 매핑을 재사용한다. 새 `otp-sessions` 를 만들지 않는 것이 핵심이다 — 세션은 유지한 채 코드만 다시 보낸다. 로그에는 otpSessionId 와 반환된 expiresIn 만 남긴다.

**3) `src/main/services/auth-service.ts`**

`apiLoginState` 의 타입을 `{ email, password, otpSessionId, otpExpiresAtMs: number | null }` 로 넓힌다. `credentialLoginApi` 가 `requestOtpSession` 응답의 `expiresIn`(초)을 받으면 `Date.now() + expiresIn * 1000` 을 `otpExpiresAtMs` 에 기록하고, 없으면 `null` 로 둔다. `expiresIn` 단위가 초라는 것은 미검증 가정이므로, 값이 비정상적으로 작거나(≤0) 크면(> 86400) `null` 로 취급해 만료 판정을 아예 하지 않는다 — 잘못된 만료 판정으로 정상 코드를 거절하는 쪽이 더 나쁘다.

`async resendOtpApi(): Promise<CredentialLoginResult>` 를 추가한다:
- `apiLoginState` 가 없으면 `{ success: false, code: "NO_SESSION", message: "로그인 세션이 없습니다. 다시 로그인해주세요." }`.
- `this.apiClient.resendOtp(otpSessionId)` 호출. 성공하면 반환된 `expiresIn` 으로 `otpExpiresAtMs` 를 갱신하고 `this._emit({ type: "otp-resent", message: "인증 코드를 다시 보냈습니다. 이메일을 확인해주세요.", timestamp: Date.now() })` 후 `{ success: false, needOtp: true }` 를 반환한다 — 재발송은 로그인 완료가 아니므로 `success: true` 가 아니고, UI 는 여전히 OTP 입력 상태에 머물러야 하므로 `needOtp: true` 다.
- 실패하면 `ApiAuthError.code` 를 `code` 필드에 실어 실패 반환하고 `login-failed` 를 emit 한다.

`submitOtpApi` 에 만료 처리를 넣는다: `verifyOtp` 를 호출하기 **전에** `otpExpiresAtMs` 가 `null` 이 아니고 `Date.now() > otpExpiresAtMs` 이면 서버를 때리지 않고 `this._emit({ type: "otp-expired", message: "인증 코드가 만료됐습니다. 재발송 후 다시 입력해주세요.", timestamp: Date.now() })` 후 `{ success: false, needOtp: true, code: "OTP_EXPIRED", message: "인증 코드가 만료됐습니다." }` 를 반환한다. `apiLoginState` 는 유지한다(재발송으로 이어져야 하므로). 서버가 만료를 어떤 코드로 표현하는지는 미검증이므로 서버 코드에 의존하지 않고 로컬 시각 비교만 근거로 삼는다.

`finishApiLogin` 에 교환 단계 이벤트를 넣는다: `acquireFaneventToken` 호출 직전 `this._emit({ type: "token-exchange-progress", message: "팬이벤트 토큰 확보 중...", timestamp: Date.now() })`, 실패 시 `credential-login-progress`/`login-failed` 대신 `this._emit({ type: "token-exchange-failed", message: ..., timestamp: Date.now() })` 를 추가로 발행한다(`login-failed` 도 함께 발행해 기존 UI 의 실패 처리가 계속 동작하게 유지한다). 이로써 "계정 로그인은 됐는데 팬이벤트 토큰만 못 얻었다"가 이벤트 스트림에서 구분 가능해진다 — Pitfall 5 가 요구한 분리다.

`credentialLoginApi` / `submitOtpApi` / `finishApiLogin` 의 모든 실패 반환에 `code` 를 채운다: `ApiAuthError` 면 그 `code`, 그 외 예외면 `"UNKNOWN"`. 서버 `message` 는 그대로 `message` 에 싣고 한국어로 다시 쓰지 않는다.

새 이벤트는 반드시 `this._emit()` 을 통해 발행한다 — `ipc-handlers.ts` 의 `auth-event` 포워딩이 이미 걸려 있으므로 `ipc-handlers.ts` 를 수정하지 않아도 렌더러까지 자동 전달된다.

기존 헤드리스 경로(`credentialLogin`, `submitOtp`, `login`, `validateToken`, `extractTokenFromCookies`, `tryAutoLogin`)는 수정하지 않는다.
