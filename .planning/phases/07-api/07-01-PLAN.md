  <behavior>
    `parseJwtExpMs(token: string | null): number | null`
    - 3분절 JWT 이고 payload 에 숫자 `exp` 가 있으면 `exp * 1000` (ms epoch) 을 반환한다.
    - `null`/빈 문자열/분절 수가 3이 아님/`exp` 가 숫자가 아님/base64 디코드 실패/JSON 파싱 실패 → 전부 `null`.
    - 어떤 경우에도 throw 하지 않고, 토큰 원문을 반환값이나 예외 메시지에 담지 않는다.

    `evaluateTokenExpiry(expMs, plannedSubmitAtMs, headroomMs): TokenExpiryState`
    - `expMs === null` → `{ status: "unknown" }` (D-11)
    - `expMs < plannedSubmitAtMs + headroomMs` → `{ status: "warning", expAt: expMs }` (D-09)
    - 그 외 → `{ status: "safe" }`
    - 경계값: `expMs === plannedSubmitAtMs + headroomMs` 는 `safe` (엄격 미만 비교)
    - 같은 입력에 항상 같은 출력, 외부 호출·시각 읽기(`Date.now()`) 없음 — 판정에 필요한 시각은 전부 인자로 받는다.

    `ApplyEngine.arm()` (기존 armed 이벤트 발행 직후)
    - `authService.token` → `parseJwtExpMs()` → `evaluateTokenExpiry(expMs, new Date(schema.applyPeriod.startAt).getTime(), RELOGIN_HEADROOM_MS)`
    - 결과가 `safe` 든 `warning` 이든 `unknown` 이든 **항상** `token-expiry-checked` 이벤트를 발행한다(재판정 시 이전 경고를 지울 수 있어야 하므로 safe 도 발행).
